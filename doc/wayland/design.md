# Native Wayland Skia host design

Status: first window runs (software wl_shm and EGL) under a nested compositor; see [Runtime state](#runtime-state-and-integration-questions). Target assembly `Uno.UI.Runtime.Skia.Wayland`, root namespace `Uno.WinUI.Runtime.Skia.Wayland`; builder extensions use `Uno.UI.Hosting` to match the existing host API. This adds a Skia desktop transport, independent of the native Android/iOS/DOM rendering layers. The [X11 service map](x11-host-map.md) inventories the checked-out fork, including additions beyond the release baseline.

## Selection and package boundary

Applications opt in with `builder.UseWayland().UseX11()`. The existing builder chooses the first supported candidate; absent `WAYLAND_DISPLAY`, connection failure, or missing required globals makes the Wayland candidate unsupported in automatic mode. `UseWayland()` does not itself reference or load the X11 assembly: the chained `UseX11()` supplies the fallback. A future shared Linux convenience builder can register both. Without a registered X11 candidate, automatic fallback cannot manufacture one.

Proposed environment override: `UNO_SKIA_HOST=auto|wayland|x11` (unset means auto). Forced Wayland reports a clear startup error instead of silently selecting XWayland; forced X11 skips Wayland. Unknown values are errors. This controls candidates registered in that order; integration must also teach the shared selector to reject incompatible earlier candidates if a global override is promised. The skeleton implements the Wayland half only. For this first API require `WAYLAND_DISPLAY`, even though libwayland also supports `WAYLAND_SOCKET`; inherited fd support is a follow-up decision.

Probe without registering any process-wide extension. Connect, obtain registry globals, perform a bounded startup synchronization, and check `wl_compositor` v1, `xdg_wm_base` v1 and `wl_shm` v1 (the guaranteed software fallback). Clamp each bind version to min(advertised, generated supported). A seat is optional for first surface creation; input devices can appear later. Optional scale, decoration and activation protocols do not disqualify the host. Record why a candidate failed. Avoid catching protocol corruption or arbitrary implementation exceptions as mere capability absence. Native load and connection failures need a specific normalized exception contract from proto.

The probe currently connects and disposes separately from Initialize; integration should retain a successfully probed connection through Create, with explicit disposal when a candidate is not chosen, to avoid a probe/create race. Recheck globals if reconnecting. Global removal triggers capability teardown; a removed required global or display disconnect terminates the selected session, never switches live windows to X11.

No root csproj is added by map ownership. Integration should mirror X11's project references to Skia, Uno.UI.Skia, Uno.Skia and Uno.Foundation.Skia, explicit assembly/root namespace, existing TFM override and transitive packaging patterns. Do not inherit X11-only LibVLC or D-Bus packages for P0. New code uses generated native entry points / typed proxies, with no reflected type discovery. Delete `Hosting/Protocol.Stubs.cs` when proto lands; it deliberately cannot connect. Registry dictionary shape and generated namespaces in that file are provisional adapters, not a new binding implementation.

## Threads and dispatch

One display connection per application host, one protocol dispatch thread, and one Uno UI thread. Every application proxy is owned by the dispatch thread; callers enqueue commands and wake an eventfd/pipe. Handle ping/pong and acknowledgements there without waiting for UI work. Copy protocol event data into immutable managed snapshots before posting to CoreDispatcher. Never retain native array/string memory beyond a callback. Input events retain order; coalesce resize/render notifications only where intermediate state is dispensable.

The loop drains pending events and outbound commands, prepares a read, flushes (poll writable on EAGAIN), then polls the display and wake fd. On wake-only readiness cancel the prepared read before running commands; on display readiness read events, then dispatch pending. Handle EINTR, disconnect and protocol errors. Roundtrip is startup-only before the read loop; do not call it while a prepared read is outstanding. Use a deadline for startup to avoid a frozen compositor hanging host selection. These constraints follow the [libwayland client API](https://wayland.freedesktop.org/docs/html/apb.html).

Uno owns application creation, XamlRootMap, layout, focus, pointer routing, window events and shutdown policy on the UI thread. Shared EventLoop can supply UI scheduling, provided CoreDispatcher.DispatchOverride and HasThreadAccessOverride are installed before Application.Start. Do not overwrite an existing dispatcher owned by another host. The dispatch thread must never synchronously wait for UI; UI does not wait for configure or buffer release. EGL may use Mesa's private event queue; rendering integration must coordinate read ownership and serialize application surface commits. GPU calls stay on the context-owning render thread. Disposal wakes polling, retires windows, drains or cancels commands, joins threads from an external thread, and only then disconnects.

## Window lifecycle

Create wl_surface, xdg_surface and xdg_toplevel; install listeners before sending the initial empty commit. Set application identity and title, negotiate decoration mode, then commit without a buffer. Collect toplevel size/state and apply them at the following xdg_surface.configure serial. Width or height zero means client chooses that dimension. Acknowledge the serial on the protocol thread; publish a configure generation containing logical dimensions, scale and state to UI/render. The renderer attaches its first matching buffer only after acknowledgement. Discard stale rendered generations instead of attaching a buffer for old geometry. These lifecycle rules follow [xdg-shell](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/stable/xdg-shell/xdg-shell.xml).

Close requests go to RaiseClosing on UI; cancellation keeps the surface alive. Otherwise unregister the XamlRoot, cancel pending render/input callbacks, dispose decoration/scale/viewport objects, destroy toplevel then xdg_surface then wl_surface, and retire buffer/native allocations safely. Programmatic Close uses the same path. Application.Exit and OnLastWindowClose complete the host run task; do not infer exit from zero windows before startup creates its first window. A display failure completes that task with an error.

Compositor configure is authoritative for maximize/fullscreen/activation. Resize is a requested content size plus constraints, never a forced compositor rectangle. Absolute Move/global screen coordinates, arbitrary raise/focus, guaranteed unminimize, and exact decorated outer bounds are unavailable in the baseline protocol. Report unsupported operations consistently rather than invent positions. Interactive move/resize needs a recent seat serial; activation-v1 needs a compositor-issued token. Minimize is a request without a reliable minimized-state acknowledgement.

Request SSD through `zxdg_decoration_manager_v1` and honor the negotiated mode. With no extension, or CSD selected, Uno draws a usable title bar, close button, borders and resize handles. Set xdg window geometry to content/decorations excluding shadows and provide serial-bearing interactive move/resize. ExtendContentIntoTitleBar changes CSD layout rather than assuming SSD can be hidden. SSD preference must not make GNOME or another CSD-only compositor unusable. App ID matches a desktop entry for taskbar identity; icon protocol support is later work.

## Scale and frame presentation

Logical layout and pointer coordinates are surface-local DIPs; allocation, damage_buffer and Skia targets use buffer pixels. Keep per-window scale independent of text scale. When both fractional-scale-v1 and viewporter are present, use preferred_scale / 120 as the rasterization scale, buffer_scale = 1, and viewport destination = logical surface size. Use protocol-specified rounding for fractional buffer dimensions (nearest integer, half rounded up), and account for the resulting exact buffer-to-logical transform in rendering. Update viewport, window geometry, pixel target and scale coherently. See [fractional-scale-v1](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/staging/fractional-scale/fractional-scale-v1.xml) and [viewporter](https://raw.githubusercontent.com/wayland-mirror/wayland-protocols/main/stable/viewporter/viewporter.xml).

Otherwise use wl_surface.preferred_buffer_scale (surface v6) if available; on older versions track entered outputs and choose a supported integer wl_output.scale (maximum of entered scales as fallback policy; retain last scale briefly when output set is empty). Surface buffer scale needs v3; v1/v2 surfaces stay scale 1. Integer allocation is logical dimensions × scale. Scale changes trigger DisplayInformation.DpiChanged, ContentSite/RasterizationScale updates, a new render generation and a redraw without changing DIP size. LogicalDpi is 96 × rasterization scale; physical monitor DPI is separate metadata. Never use output millimetres to override the compositor's preferred scale.

Default backend proposal: EGL/GLES using libEGL plus libwayland-egl's wl_egl_window, falling back to CPU Skia + wl_shm. Software is the reference backend and must work without a GPU. Use existing SkiaSharp dependencies. wl_shm buffers use mmap-backed fd storage with validated dimensions/stride/size; do not reuse until wl_buffer.release. Resize retains unreleased old buffers. Request wl_surface.frame when submitting, coalesce subsequent invalidations until callback, and stop spinning while obscured. Frame done is permission to schedule, not a buffer release. EGL manages its buffer attachments; do not duplicate them with wl_shm commits. EGL resize and scale state must belong to the same generation. Optional Vulkan uses VK_KHR_wayland_surface and shared VulkanContext later; do not toggle the existing X11 rendering flags.

## Input and desktop services

Bind dynamic wl_seat capabilities. wl_pointer coordinates stay logical, map Linux buttons to Uno button state and preserve frame batching, timestamps, enter/leave and wheel/axis source semantics. Pointer capture inside the client is managed; pointer confinement/relative motion require optional protocols and explicit API support. Track focus surface and input serial per seat, not a process-wide latest serial. Use cursor-shape-v1 where supported; libwayland-cursor and a cursor surface provide fallback. Scale cursor pixels and hotspots coherently.

wl_keyboard keymap fd provides xkbcommon state; apply compositor modifier masks, add the xkb keycode offset to evdev codes, map VirtualKey and Unicode separately, and implement repeat_info on the UI scheduler. Stop repetition on focus loss, capability loss or key release. xkb compose handles dead keys when no text-input integration is active. Touch ids map to stable Uno pointer ids through up/cancel/frame. Never open /dev/input or use libinput for desktop client input; reuse framebuffer xkbcommon concepts only.

Use text-input-v3 when advertised for preedit/commit, cursor rectangle, surrounding UTF-8 text and focus enable/disable. Convert byte offsets to managed text offsets carefully. Do not deliver both keyboard-derived text and IME committed text. Unsupported text-input-v3 means keyboard/compose still works; full IME parity needs another negotiated compositor-supported protocol or shared Linux IME service design.

P1 desktop services: wl_data_device selection and drag/drop with fd streaming, MIME negotiation, correct seat serials and asynchronous cancellation; reuse existing D-Bus portal FileChooser/Settings adapters after extracting their X11 parent coupling. Export xdg-foreign parent handles and unexport them when the request completes. Validate file URI parsing and cut/copy conventions against other file managers. No XID-based picker parenting or native element reparenting is portable to Wayland. Portal adapters can continue using the already present Tmds dependency after extraction; no new dependency is required by the host skeleton.

## Popups and multiple windows

Code review confirms ordinary popups register in XamlRoot.VisualTree.PopupRoot (`src/Uno.UI/UI/Xaml/Controls/Popup/Popup.Base.cs:96`); PopupRoot is a Canvas (`PopupRoot.cs:18`). They render in the existing Skia surface, including light-dismiss input. No xdg_popup is needed for ordinary MenuFlyout, ComboBox and ToolTip implementation. They remain constrained by the surface; native overflow popups would require a separate design with positioners, serial-bearing grabs and popup_done. This is source inspection, not a runtime verification of every control.

Each Window has its own surface, shell objects, configure generation, renderer, scale/output membership and XamlRoot host. Route seat focus by proxy identity. Keep a UI-owned managed window map and a protocol-owned proxy map; use generation tokens so queued events cannot touch destroyed windows. Shared display failure closes all windows. Support more than one Window from the start rather than copying X11's per-window display/event thread pattern. Secondary assembly-load-context cleanup needs explicit ownership and shared dispatcher integration later.

## Shared hooks and ownership boundary

Do not make platform internals public just to compile a host. Add `InternalsVisibleTo("Uno.UI.Runtime.Skia.Wayland")` where needed:

- `src/Uno.UI/AssemblyInfo.skia.cs`: IPlatformHostBuilder, IXamlRootHost, XamlRootMap, ISkiaApplicationHost, Application.Host, Window.RootElement and NativeWindowWrapperBase/factory contracts.
- `src/Uno.UWP/AssemblyInfo.skia.cs`: EventLoop, CoreDispatcher overrides and WinRT service extension contracts.
- `src/Uno.Foundation/AssemblyInfo.cs`: ApiExtensibility and internal helpers used by existing desktop hosts.
- `src/Uno.UI.Dispatching/AssemblyInfo.cs`: native dispatcher priorities/hooks used by the host.
- `src/Uno.UI.Runtime.Skia/AssemblyInfo.cs`: renderer/shared Vulkan helpers as selected by render. SkiaHost itself is already public.
- `src/Uno.Foundation.Logging/AssemblyInfo.cs`: internal logging helpers if required by render/input.
- Audit `src/Uno.UI.Composition/AssemblyInfo.skia.cs` access when render lands; add a friend only for actual internal usage. No public API expansion is currently justified.

Some friend declarations may come from shared imported build items rather than the assembly-local file; verify the evaluated build before duplicating them. All additions outside Hosting/Builder are integration work, not changes in this map task. Reuse LinuxLauncherExtension already in `src/Uno.UWP/System/LinuxLauncherExtension.skia.cs:11`. Extract portal/theme/text-scale adapters from X11 to shared Linux code, using an explicit native-parent exporter interface. Expose renderer lifecycle internally through typed factories, resize generations, frame requests and disposal, and input factories through IXamlRootHost. Avoid registration in static constructors that runs merely by probing a builder.

## Upstreaming plan and validation gates

File a public enhancement issue on unoplatform/uno describing native Wayland sharp scaling, supported compositor matrix and API limits. Every implementation PR references that issue and uses the repository PR template. Suggested reviewable PR order:

1. Public design/API and shared Linux service extraction; friend assembly declarations and packaging/host selection policy. Preserve existing X11 behavior.
2. Reproducible protocol generator and pinned XML/licenses; AOT-safe libwayland bindings, fd ownership, registry/version tests and wakeable dispatch loop.
3. First software window, configure/ack/close, UI dispatcher, multi-window lifecycle and CSD fallback; runtime smoke tests under nested compositor.
4. Pointer/keyboard/touch/cursor, integer/fractional scale, output changes and frame pacing; LinuxFiles usability tests.
5. EGL acceleration and backend fallback; GPU/software screenshots and fractional sharpness comparisons.
6. Clipboard, file DnD, portal parent export and IME; desktop interoperability tests.
7. Optional Vulkan, native elements/media and advanced popup/activation capabilities as separate proposals.

Runtime gates: initial configure before first buffer; close cancellation then accepted close; repeated create/destroy; multi-window focus; resize storms and mixed-scale monitor moves; integer-only and fractional compositor paths; CSD and SSD; keyboard repeat/compose and IME; clipboard/DnD large async transfers; compositor disconnect; forced selection errors and automatic X11 fallback. Test both GPU and software, publish a trimmed and NativeAOT sample, and verify no reflection/new dependency regressions. Record compile and runtime evidence separately. Build failures must not be treated as runtime evidence.

## Runtime state and integration questions

Implemented: the probed connection is handed to the selected host; a wakeable dispatch thread (prepare_read / poll / read_events / dispatch_pending) also runs commands posted with `WaylandDisplay.Post`; the X11-style EventLoop UI dispatcher; one wl_surface + xdg_surface + xdg_toplevel per Window with app id, title, SSD request, configure/ack, compositor close (cancellable through RaiseClosing) and ordered teardown; per-window render thread driving wl_shm (or EGL when available) with frame callbacks; fractional-scale-v1 + viewporter and preferred_buffer_scale; IDisplayInformationExtension, pointer/keyboard input sources, cursor (cursor-shape-v1 or libwayland-cursor surface) and launcher registrations; exit on Application.Exit or last window close.

Thread ownership as implemented: protocol events fire on the dispatch thread under `SyncRoot` and only copy data, acknowledge (ping, configure) and post. Requests may be issued from any thread under `SyncRoot`; proxies whose events must not be missed are created and subscribed in one `SyncRoot` section. Configure, scale and close are posted to the UI thread with `NativeDispatcher.Main`. Each window's renderer, frame scheduler and Skia surfaces belong to its render thread; frame-done and wl_buffer.release events are posted back to it, so the scheduler stays single-owner. Uno draws into a persistent layer (CompositionTarget clips later frames to their damage): a GPU retained layer presented straight into the EGL window surface, or a raster surface copied into the wl_shm buffer. Hidden windows keep producing UI frames at a low rate when frame callbacks stop. Every wl_output is tracked (wl_output v4 name/description, hotplug); the window's current output (last entered) feeds DisplayInformation resolution/size, and surfaces older than v6 take the largest entered output scale. A compositor disconnect or protocol error stops dispatch with an IOException naming the error, which the host run loop logs and rethrows; startup gives up after 5 s instead of hanging host selection.

Remaining: CSD when the compositor selects or lacks SSD; discard frames rendered for a stale scale/size generation (one frame can show the old scale after a scale change); multiple seats; clipboard, DnD, portals, text-input-v3, application view and native OpenGL wrapper registrations; secondary-ALC cleanup. A successful probe is only consumed by Initialize: the shared builder always creates the first supported candidate, but probing without building leaves the connection open until exit. Existing NativeWindowWrapperBase Hide/Destroy are nonvirtual; actual unmap/remap needs a shared hook audit before parity is claimed.
