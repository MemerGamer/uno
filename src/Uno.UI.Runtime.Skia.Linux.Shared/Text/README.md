# Linux text rendering

The X11 and Wayland hosts register `LinuxTextRenderingExtension` before creating application fonts. Its immutable startup snapshot reads the default fontconfig pattern through `libfontconfig.so.1`. It includes antialiasing, hinting/hintstyle, rgba, lcdfilter and autohint. It does not match individual font faces or sizes, or watch for configuration changes.

Missing/invalid properties fall back to antialiasing on, Normal hinting and unknown pixel geometry (grayscale). If fontconfig itself is unavailable (library/API failure or failed pattern creation/substitution), the extension preserves the existing font hinting and autohint flags; ordinary Skia fonts retain Normal hinting. Explicit hinting overrides still apply on failure. `hinting=false` takes precedence over hintstyle. Fontconfig's medium hinting maps to Skia Normal. Subpixel glyph positioning and baseline snapping are preserved.

Startup overrides:

- `UNO_SKIA_TEXT_HINTING=none|slight|normal|full`
- `UNO_SKIA_TEXT_RGBA=none|rgb|bgr|vrgb|vbgr`

Invalid values keep the fontconfig preference. An rgba override still obeys the presentation safety gates and does not override `antialias=false`.

LCD geometry is supplied to the content surface where text rasterizes: the GPU retained layer or the software content surface. The recorded frame must have a square, opaque `RootVisual` or `XamlIslandRoot` background covering the frame, with no root clip or transform. The picture's transparent clear is followed by that root background; the host's initial clear alone is insufficient. Rotated, skewed, mirrored or perspective text visuals disable LCD for the entire frame, including cached child pictures. Geometry changes recreate the content surface and redraw the entire frame. On X11 they preserve the presentation surface and airspace resources when pixel dimensions are unchanged; software rendering rewraps the existing bitmap without reallocating its pixels or XImage.

X11 requires RandR 1.3 queries and change notifications, integer rasterization scales, and agreement between every intersected output (including cloned outputs) and the configured physical order. Intersected CRTCs must have normal rotation, an identity presentation transform, matching mode/buffer dimensions and disabled panning. Failed/unknown queries, conflicting orders and windows not fully covered by one verified CRTC use grayscale. Window configure and RandR screen/CRTC/output/property events invalidate the cached output geometry and request a redraw. Wayland additionally requires entered outputs to agree with the configured order, use normal output transforms and have the same integer scale as the buffer. Unknown outputs, conflicting orders, mixed scales and fractional presentation use grayscale. Compositor-side effects and panel-internal scaling cannot all be detected; `UNO_SKIA_TEXT_RGBA=none` is the escape hatch.

The [Skia scaler](https://github.com/google/skia/blob/chrome/m119/src/core/SkScalerContext.cpp) falls back to grayscale for unknown geometry. The raster backend does **not** universally disable LCD for translucent paint or rotated glyphs: native SkiaSharp 3.119.0 probes produce chromatic pixels in both cases. Uno explicitly uses grayscale fonts for non-opaque/effect paints and gates frame geometry for transforms. Ordinary [saveLayer surfaces](https://github.com/google/skia/blob/chrome/m119/src/core/SkCanvas.cpp) discard geometry unless LCD preservation is explicitly requested, so opacity/effect layers use grayscale.

## Transparent roots and opaque controls

Desktop WinUI windows use `DesktopWindow` → `DesktopWindowXamlSource` → `XamlIslandRoot`. The frame check accepts this root under the same opacity/coverage/transform rules as `RootVisual`; accepting only `RootVisual` would disable LCD in every desktop window regardless of opacity.

A transparent root disables LCD for the whole frame, even if a particular TextBlock or list row appears over an opaque backing. `SkiaRenderHelper.CanUseLcdRoot` snapshots the root-opacity contract while recording; `CompositionTarget.Draw` replaces the host's requested geometry with `Unknown` when that contract fails. Hinting still applies to the fonts, so a capture can show changed hinting with an unchanged chromatic-pixel count. A second independent Wayland gate requires known entered-output subpixel order, normal transform and matching integer scale; `UNO_SKIA_TEXT_RGBA=rgb` cannot bypass either gate.

For windows using a supported `SystemBackdrop`, `Window.ApplyTransparentBackgroundsForBackdrop` replaces root and descendant backgrounds with transparent brushes. The compositor's backdrop is outside the retained content surface and cannot supply opaque destination pixels to text rasterization. The host's white initialization clear also cannot help: `RenderPicture` clears transparent and the recorded frame starts with another transparent clear.

LCD can be mathematically safe per draw when **all glyph/filter footprint destination pixels are already opaque**, the text paint and final presentation are safe, and no later operation moves or filters the resulting subpixel coverage. This is a requirement the caller must prove, not an automatic per-pixel safety check in Skia. The [raster LCD blitter](https://github.com/google/skia/blob/chrome/m119/src/core/SkRasterPipelineBlitter.cpp) builds an LCD coverage pipeline without scanning destination alpha or switching translucent destination pixels to grayscale.

Uno selects render fonts while recording per-visual pictures (`Visual.PaintStep`), before replay into the retained layer. Those recorders have no destination pixels or knowledge of preceding sibling/ancestor background draws. Cached subtree pictures also use local transforms, while replay can apply different ancestor transforms. Checking a TextBlock's brush or the final retained surface's alpha would therefore not prove opacity at the time of the draw, especially at rounded/antialiased edges, clips, backdrop/effect layers or after background changes. Safe per-run LCD needs draw-order-aware backing coverage, glyph-footprint containment, cache invalidation and replay/effect handling. That is not a simple gate removal; the conservative frame check remains. For LCD today, the app must supply an opaque square root background and satisfy the output/transform gates; text over a window backdrop stays grayscale.

`lcdfilter` is read and logged, but cannot be applied through SkiaSharp's managed API. [Skia's FreeType library](https://github.com/google/skia/blob/chrome/m119/src/ports/SkFontHost_FreeType.cpp) uses `FT_LCD_FILTER_DEFAULT`; other fontconfig filter choices require native SkiaSharp support. Full hinting may also be reduced to Normal by Skia when LCD is unavailable, and Skia adjusts hinting for rotated glyphs.

The settings and override tests live in `Uno.UI.Runtime.Skia.Wayland.Tests/Given_LinuxFontRendering.cs`; Wayland output safety tests are in `RenderLogicTests.cs` and X11 order/coverage tests in `Given_X11TextPixelGeometry.cs`.
